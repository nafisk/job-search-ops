# Posting verification

Record employer, exact title, published requisition, observed URL, actual checked time, responsibilities, required/preferred qualifications, location, office cadence, remote residency restrictions, and availability evidence. Cite short exact excerpts where wording affects a decision. Never invent requisitions from arbitrary URL tails or rewrite links to guessed slugs.

- Snippets, caches, HTTP 200, and generic careers homepages cannot establish an open role. Read the live exact posting and an active application control/route. Publication date is not verification time.
- An explicit official unavailable notice establishes closure. Redirects, login walls, timeouts, challenges, and unreadable pages establish access gaps. Try another supported reader/browser if available; after three attempts across methods, retain the gap and continue. Do not bypass controls or install tools to fill a count.
- Read requirements throughout the page, including specialty years and degree alternatives. A bachelor's-plus-five OR master's-plus-three path requires the applicant's actual degree. Preferred years are not required years; numbered titles supply no numeric minima. Explain ambiguous ranges.
- Missing material required evidence means needs clarification, not passed or failed. A known mandatory conflict excludes a match; transferable skills do not waive a mandatory credential.
- A remote label alone cannot prove country/state eligibility. Mandatory office attendance overrides generic remote wording. Unresolved contradictory policies need clarification.
- Recheck candidates when material time has elapsed or new evidence indicates changes. Report the actual last check; never refresh old timestamps without reading.

Fictional example: an Engineering Solutions Developer dominated by customer-ticket escalation is outside a backend product-engineering search despite repeated Java keywords. An API/service owner can be relevant even if its title omits backend.
