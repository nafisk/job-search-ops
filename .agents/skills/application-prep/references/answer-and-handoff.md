# Answer drafts and handoff

## Drafts

Use question / proposed answer / factual basis / unresolved detail. Do not invent salary expectations, start dates, authorization, sponsorship, clearance, background-check outcomes, or credentials. No sponsorship needed does not establish citizenship. Optional sensitive self-identification belongs to the user; never infer it.

Do not turn assisted work into sole ownership, projected savings into realized savings, or desired qualifications into applicant facts. Keep uncertainty visible; do not put private evidence paths/raw correspondence into employer-facing copy.

## Browser routes

Use supported controls only for chosen, authorized pages. Inspect the actual destination before calling a handoff successful. A posting is not necessarily an accessible application form; record them separately. If a button could create an application rather than only navigate, leave it for the user. Login, permission, and security challenges remain user steps under host policy; never bypass them or extract cookies.

Inspect existing tabs before retrying an uncertain opening. Stop after three access attempts per role across methods; return the blocker. Never open unrequested replacements to meet a count.

## Simplify

Provide the verified link and truthful draft packet. The user opens it where they use Simplify, invokes the extension, reviews every answer/attachment, and submits. Do not claim a bundled adapter, guaranteed ATS support, profile synchronization, or tested integration. Without browser tools, still supply drafts and clearly labeled unverified links from supplied material.

## Status

Keep posting availability, route accessibility, preparation, and submission separate. Example: posting verified open; login required; drafts ready; submission unknown. Exact-role user confirmation can establish submission; a generic employer acknowledgment or closed tab cannot.
