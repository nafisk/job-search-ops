# Initial redesign assessment

Inspection covered root routing/onboarding, source runbooks, screening and application reconciliation, shared setup/queue/writer code, application batches, and distribution checks. Runtime code remains unchanged.

| Preserve | Basic adaptation |
| --- | --- |
| Full-description evidence and required/preferred distinctions | Resume-backed qualification comparison, explicit unknowns |
| Source freshness, location restrictions, honest coverage gaps | Official posting checks, office/residency details, actual timestamps |
| Exact employer/requisition identity and submission evidence | Deduplicate roles; never infer Applied from tabs |
| Referral holds and verified aliases | User-supplied restrictions without requiring a registry |
| Private data and reviewed export inventory | No personal data in skills; strict export allowlist retained |
| One writer, readbacks, uncertain-effect journals | Retained in advanced runtime, not a basic prerequisite |

## Friction removed

A small company search previously required a private installation, strict JSON profile, tracker binding, helper chats, queue packets, native evidence receipts, watchlist seeding, and pilots. Opening applications depended on saved tracker jobs. These safeguards suit ongoing coordinated operations but are disproportionate to a one-session shortlist.

Keyword overlap could admit support-oriented roles. Policy ceilings could be mistaken for actual experience. Cached postings could appear usable until live checked. The new skills separate duties from keywords, facts from criteria, fit from availability, and preparation from submission.

## Implementation choices

Three instruction-only packages each contain their own small reference and fictional preferences example. Limited repetition keeps individual installations complete. There is no runtime dependency on the old Python code: porting its strict profiles/ledgers would reintroduce the setup burden.

Chat is the default. YAML is optional, user-selected documentation rather than a strict parser/schema. A larger search pauses after three samples unless explicitly overridden. Scarce matches produce fewer results.

No automatic migration or changes to private settings, saved prompts, trackers, resource IDs, queues, or schedules. Advanced workflows keep their original gates. Basic skills neither scan nor reset that state.

A maintainer-only script checks package closure and references. Behavioral scenarios are reviewed qualitatively rather than pretending string checks prove agent behavior.

## Limits and next improvement

Agent judgment and tool quality still determine semantic accuracy. Application history can be incomplete; availability changes; Simplify remains a user handoff. Official Codex installation instructions were researched, not installed. No cross-host/live integration success is claimed.

Smallest useful next improvement: exercise the three-sample calibration checkpoint with a consenting user's real preferences and capture corrections before completing ten. Development uses fictional cases only.
