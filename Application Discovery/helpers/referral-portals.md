# Run a referral portal search

Use the `main` gate in the [shared source checks](../docs/operations.md#start-a-discovery-source). In coordinated mode, search the companies the user named. For a legacy recurring portal run, use its saved scope.

1. **Load approved routes.** Read `sources.referral_companies_path`, `<installation>/portal-registry.json` and the live **Referral Watchlist**. Resolve scope or contact conflicts, keep contact evidence private and report any missing [setup](../docs/referrals.md). Use confirmed company keys and merge aliases only within the same employer unless the user approved a broader match.
2. **Check coverage.** Reopen the saved [filtered links or browser steps](../docs/referrals.md#build-links-for-repeat-runs). Verify the employer, active filters and complete pagination. Use public reads for official boards and a supported browser for dynamic pages. Follow the [portal checks](../support/toolkit/PORTALS.md#validate-before-reuse) and [access rules](../docs/operations.md#ownership-and-source-boundaries). When a route fails, revalidate it or record the gap and resume cursor.
3. **Screen roles.** Read the full official posting and apply the [screening rules](../support/toolkit/SCREENING.md). Record the decision and evidence for each candidate. Count zero only after covering the declared scope. Mark a specific role closed only with positive closure evidence or a complete authoritative comparison that covers it.
4. **Hand off.** Queue the `portal` packet through the [shared handoff](../docs/handoffs.md#producer-handoff). Include verified identities, screening decisions, coverage and any private referral facts. The coordinator saves the results.
