## Setup and execution

- Reuse the selected user's confirmed facts and canonical private settings. Examples are shapes, not real choices, facts, accounts or authorization. Never substitute another person's deployment.
- Connect only selected tools and respect the requested operation. Application Workflow's initialization, `doctor`, writer and scheduling rules do not apply to standalone Resume, LinkedIn or Outreach work.
- Keep operational private data outside the repository and exports. Preserve existing locations, IDs, history, user edits and unrelated live workflows. Read only private material relevant to the selected scope.
- Follow each guide's setup, pilot and run boundaries. Outreach research/drafting and application batches require their own human requests; discovery does not start them. The user sends recruiter messages and fills/submits applications. LinkedIn profile edits follow that runbook's reviewed approval process.
- Finish operational setup with the [private setup summary](ONBOARDING.md#your-setup-summary). Link authoritative records and report actual verification/gaps; the summary grants no permissions and overrides no execution holds.

## Repository maintenance

Inspect current changes before editing and preserve unrelated work. Keep detailed procedures in their owning workflow; root files route readers instead of duplicating those procedures. Runtime paths and the existing batch prerequisites are unchanged by navigation cleanup.

Review intended additions/moves in [RELEASE_FILES.txt](<Application Workflow/support/RELEASE_FILES.txt>) and use the existing [verification guide](<Application Workflow/docs/verification.md>) for appropriate checks. Documentation checks cannot certify a live account, browser pilot or tracker write. Never exercise live workflows merely to validate repository navigation.
